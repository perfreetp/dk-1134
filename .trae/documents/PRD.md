# 通勤拼车移动应用产品需求文档 (PRD)

## 1. 产品概述

### 1.1 产品名称
**顺路拼车** - 通勤出行新选择

### 1.2 产品定位
一款面向固定线路通勤人群的智能拼车匹配平台，通过算法优化帮助车主和乘客快速找到顺路同行伙伴，提升出行效率，降低通勤成本。

### 1.3 核心价值主张
- **效率提升**: 智能路线匹配，一键找到顺路伙伴
- **成本优化**: 分摊出行费用，经济环保
- **信任保障**: 信用体系+双向评价，构建安全出行社区

---

## 2. 用户画像与使用场景

### 2.1 目标用户
| 用户类型 | 核心需求 | 痛点 |
|---------|---------|------|
| 车主 | 降低通勤成本，找到稳定同行乘客 | 油费负担重，独驾无聊 |
| 乘客 | 省钱省心，不用挤公交地铁 | 打车贵，公交慢且不准时 |

### 2.2 典型使用场景
- **早高峰通勤**: 家住郊区，公司在市中心，每天固定路线
- **跨城通勤**: 两城交界区域，每周五天往返
- **周期出行**: 每周固定几天需要用车，希望找到固定拼友

## 3. 功能需求规格

### 3.1 五大核心页面

#### 3.1.1 首页 - 路线匹配
**功能描述**: 用户查看和匹配顺路行程的核心入口

**功能清单**:
- 常用上下车点管理（支持多个常用地点）
  - 添加/编辑/删除常用地点
  - 设置默认上下车点
  - 地图选点或搜索地址
- 上班到达时间设置
  - 设置期望到达目的地的时间
  - 支持工作日/周末不同设置
- 顺路车辆/乘客列表
  - 展示匹配的顺路行程卡片
  - 显示绕路距离（≤3km筛选）
  - 显示预计费用（按公里数+起步价计算）
  - 显示出发时间、座位余量
  - 显示车主/乘客信用评分
- 一键发起拼车申请
- 筛选与排序功能
  - 按出发时间排序
  - 按绕路距离排序
  - 按信用评分排序

#### 3.1.2 发布行程页
**功能描述**: 车主发布自己的行程供他人拼车

**功能清单**:
- 单次行程发布
  - 选择出发地（常用点或地图选点）
  - 选择目的地（常用点或地图选点）
  - 设置出发时间
  - 设置座位数量（1-4座）
  - 设置每座位价格
  - 添加行程备注
- 周期行程发布
  - 选择重复周期（工作日/自定义）
  - 设置有效期
  - 自动复制到各日期
- 路线预览
  - 显示推荐路线
  - 标注上下车点
- 绕路距离计算
  - 自动计算绕行额外里程
  - 显示对乘客的影响

#### 3.1.3 订单确认页
**功能描述**: 订单创建、确认与管理的核心流程

**功能清单**:
- 拼车申请管理
  - 查看申请列表
  - 车主审批乘客申请
  - 乘客等待确认状态
- 座位数量确认
  - 实时显示剩余座位
  - 超额提醒
- 订单详情展示
  - 行程信息汇总
  - 费用明细
  - 双方信息预览
- 订单状态流转
  - 待确认 → 已确认 → 进行中 → 已完成
  - 取消订单与退款处理

#### 3.1.4 消息页
**功能描述**: 用户间沟通的即时通讯中心

**功能清单**:
- 会话列表
  - 展示所有拼车相关的对话
  - 未读消息计数
  - 最后一条消息预览
- 聊天详情
  - 文字消息发送
  - 快捷回复模板
  - 行程信息卡片嵌入
- 出发提醒推送
  - 出发前30分钟提醒
  - 迟到提醒
- 消息通知设置

#### 3.1.5 我的页面
**功能描述**: 用户个人信息与设置管理中心

**功能清单**:
- 个人中心
  - 头像与昵称设置
  - 信用信息展示（评分、认证状态）
  - 出行统计（拼车次数、节省金额）
- 常用路线管理
  - 查看已保存路线
  - 编辑/删除路线
  - 设置默认路线
- 发票与备注管理
  - 发票抬头设置
  - 常用备注模板
- 黑名单管理
  - 添加/移除黑名单用户
  - 查看黑名单列表
- 评价管理
  - 查看历史评价
  - 互评功能
  - 投诉与反馈

## 4. 数据模型设计

### 4.1 核心实体

#### 用户 (User)
```
- id: string
- name: string
- avatar: string
- phone: string
- creditScore: number (300-850)
- isVerified: boolean
- createdAt: Date
```

#### 常用地点 (Location)
```
- id: string
- userId: string
- name: string
- address: string
- latitude: number
- longitude: number
- isDefault: boolean
```

#### 行程 (Trip)
```
- id: string
- driverId: string
- origin: Location
- destination: Location
- departureTime: Date
- availableSeats: number
- pricePerSeat: number
- detourDistance: number
- status: enum (active, completed, cancelled)
- isRecurring: boolean
- recurringPattern: string (可选)
```

#### 订单 (Order)
```
- id: string
- tripId: string
- passengerId: string
- pickupLocation: Location
- dropoffLocation: Location
- seats: number
- totalPrice: number
- status: enum (pending, confirmed, inProgress, completed, cancelled)
- createdAt: Date
```

#### 消息 (Message)
```
- id: string
- conversationId: string
- senderId: string
- content: string
- type: enum (text, tripCard, system)
- createdAt: Date
- isRead: boolean
```

#### 评价 (Review)
```
- id: string
- orderId: string
- reviewerId: string
- revieweeId: string
- rating: number (1-5)
- comment: string
- createdAt: Date
```

## 5. 非功能需求

### 5.1 性能要求
- 页面加载时间 < 3秒
- 路线匹配算法响应时间 < 2秒
- 消息推送延迟 < 5秒

### 5.2 安全要求
- 用户数据加密存储
- 敏感操作需二次确认
- 位置信息脱敏处理

### 5.3 兼容性要求
- 支持 iOS 12+ 和 Android 8+
- 适配主流屏幕尺寸（375px - 428px 宽度）

### 5.4 可用性要求
- 核心流程操作步骤 ≤ 5步
- 关键按钮点击区域 ≥ 44px
- 支持手势操作（滑动、点击）

│   ├── 时间设置弹窗

│   ├── 时间日期选择器
│   └── 价格设置滑块
├── 订单确认
│   ├── 申请列表
│   └── 订单详情
├── 消息

    ├── 个人资料
    ├── 常用路线

2. 发布（加号图标）
3. 订单（列表图标）
4. 消息（消息图标）
5. 我的（用户图标）

## 7. 风险与挑战

### 7.1 用户信任问题
- 陌生人拼车存在安全顾虑
- 需要完善的信用评价体系

### 7.2 匹配效率问题
- 用户基数不足可能导致匹配成功率低
- 需要引导用户完善行程信息

### 7.3 取消与违约
- 临出发前取消影响对方出行
- 需要明确的违约处理机制
